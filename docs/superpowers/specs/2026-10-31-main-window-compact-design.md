# 主窗口紧凑化改版设计

- 日期：2026-10-31
- 分支：`feature/main-window-compact`（基于 develop `ef918fe`）
- 状态：已确认设计，实施中

## 背景与目标

主窗口当前为 780×540 固定尺寸，卡片网格 `auto-fill minmax(160px, 1fr)` 在 780 宽下恰好排成 4 列。实际使用中：

- 宽度被 4 列挤满（每卡约 178px，长明细换行）；
- 纵向大数字区占卡片约 1/3 高度（40px 数字 + 上下 30px 留白 + 分隔线）；
- 仅 4 个供应商时窗口下半部分近 40% 纯空白。

目标：参考 Traffic Monitor「内容多大、窗口多大」的形态，改为固定紧凑布局，3 列、信息密度更高、关键数字仍突出。

## 决策

| 项 | 决策 |
| --- | --- |
| 窗口尺寸策略 | 固定紧凑尺寸（不做高度自适应） |
| 窗口尺寸 | 780×540 → **720×520**（宽度与 Traffic Monitor 主窗口一致） |
| 网格 | `repeat(3, minmax(0, 1fr))`，gap 15，面板 padding 16 |
| 卡片主数字区 | 左对齐：30px 数字 + 同行右侧 12px 灰标签，上下留白加大以突出剩余值（注：「留白加大」与本表 §布局规格及实现相反——实现为主数字区自身留白 16px/14px 收窄至 6px/2px，纵向空间让给卡片 padding 与明细行距，以实现为准） |
| 配额行 | 名称 + 迷你进度条 + 百分比 + 重置时间（两行紧凑排布，容纳长重置文案） |
| 禁用供应商 | 主页面不再显示（设置页仍可见其启停状态） |
| 顶栏 | padding 12px 保持，logo 呼吸光晕改静态微光 |
| 范围 | 主窗口：纯前端布局 + `tauri.conf.json` 尺寸；托盘菜单：新增标题值右对齐（Rust，见下文追加需求） |

## 布局规格

### 窗口与网格

- `src-tauri/tauri.conf.json`：`width: 720`、`height: 520`（与 Traffic Monitor 主窗口 `NSWindow` 尺寸一致）；其余窗口属性（透明、HUD、不可缩放）不变。
- `.usage-panel` padding 16px；`.card-grid` 固定 3 列、gap 15px，行高由内容决定（不拉伸：单行供应商时卡片不会被撑高）。
- 实测高度预算：顶栏 51 + 面板上下 padding 32 + 两行卡片（约 380px）+ 行距 15 ≈ 478，520 高留有约 40px 呼吸空间，保证两行供应商完整可见；三配额卡或超过 6 个供应商时面板滚动（固定尺寸的已知取舍）。
- 删除失效的 `@media (max-width: 540px)`。

### 卡片（`.p-card`）

- padding 20px，圆角 12px，样式沿用现有玻璃卡片；卡片内纵向间距较上一版整体放大 1/4。
- 结构自上而下：
  1. 头部：24px 品牌 logo + 15px 名称（`已禁用` 卡不渲染），下间距 12px；
  2. 主数字：30px/700 左对齐，标签同行右侧 12px 三级文字；上下留白为 6px/2px + 下间距 12px，作为视觉焦点；
  3. 余额拆分（仅人民币余额卡）：一行 12px 三级文字 `赠 ¥x · 现 ¥y`；
  4. 用量/配额明细：13px，行距 gap 10px；
  5. 配额行：上行为名称 + 百分比，下行为 4px 迷你进度条 + 10px 重置时间（超长省略），行内 gap 5px。
- 告警：保留边框与数字变色，新增卡片左侧 2px 竖色条（黄/红）；损坏的错误卡同样沿用红色边框并展示错误文案。

### 顶栏

- `.app-header` padding 保持 12px 16px 12px 76px（左侧 76px 为红绿灯让位）。
- `.app-title-logo-wrap` 呼吸动画改为静态微光，保留圆角与描边。

### 进度条语义

- 宽度按 `remaining_percent`（0–100）填充；颜色：>20% 绿、≤20% 橙、=0 红（与主数字告警色一致）。

### 空态与加载

- 主页面过滤 `enabled === false` 的供应商；过滤后为空按「暂无服务商」空态处理。
- 既无余额、无用量、也无配额的卡展示「暂无数据」占位（与托盘菜单口径一致）。
- 加载/错误/空态布局沿用现有居中样式，自动适配 720×520。

## 托盘菜单值右对齐（追加需求）

- 需求：供应商标题行的「剩余进度或余额」放到最右边并居右；若该供应商下方有明细子项，则保持现有 `名称 — 值` 样式。
- 实现（`scheduler::align_menu_titles`）：
  1. 先求菜单所有行的最大文本宽度：标题行按是否有品牌 logo 加 23.8pt 图标列缩进（AppKit 实测：18pt image 的标题缩进 = image 宽 + 5.8），明细行原样；
  2. 对无明细子项的标题，在名称与值之间补空白（普通空格 → thin space → hair space），使值右边界与最宽行末尾对齐（误差 < 1pt），同时去掉分隔用 `—`；
  3. 有明细子项的标题不处理。
- 测量：`menu_align::MenuTextMeasurer` 用 `NSFont.menuFont` + `NSString.sizeWithAttributes:`。muda 0.19 未暴露 NSMenuItem 原生句柄，无法使用 attributedTitle 右制表位或 NSMenuItem.badge，只能按空格补齐。
- 首建菜单与原地 `set_text` 刷新两条路径都调用；测量失败（非 macOS、字体查询失败）整体退化为原样式。
- 已知限制：原生菜单在文本右侧保留键等效/子菜单箭头留白（约 30pt），补空格无法消除——补得越多菜单整体越宽，值始终与菜单窗口右边保持同一留白。因此「最右」以菜单文本内容右边界为准。

## 验收标准

1. 720×520 窗口下，5 个供应商排成 3+2 两行、无滚动条、底部留白适中。
2. 卡片明细不换行（除重置时间按需省略）；配额行含迷你进度条与重置信息。
3. 低余额/无余额卡左侧色条可见，数字颜色随告警级别变化。
4. 禁用的供应商不出现在主页；设置页可正常增删改并滚动。
5. 托盘菜单中无明细子项的供应商（如 Kimi API、DeepSeek、Anthropic）值右对齐到同一列、与最宽明细行末尾一致；智谱、Codex 等有子项的行保持 `名称 — 值`。
6. `npm run build`、ESLint、`cargo test`、`cargo clippy` 通过。

## 不在本次范围

- 窗口高度随供应商行数自适应；
- 卡片悬停动效、更多交互动效。
